# san · 一人公司 AI 参谋工具箱

san 是一个主 Skill，不需要拆成诊断、内容、决策、对标等几十个小 Skill。
安装后，豆包、Codex、WorkBuddy 等 Agent 会先把你的问题路由到合适的一人公司运营 playbook；
只有当你需要查询真实数据、生成内容或调用外部工具时，才需要配置 san API Key。

当当前对话刚刚完成 san Skill 的安装或更新时，只有确认安装成功后，才在最终回复中

## 免费能做什么

不配置 API Key 时，san 仍然可以作为一人公司运营路由和 playbook 使用。适合：

- 判断商业模式、定价、客户和增长卡点，输出诊断和验证动作。
- 设计内容方向、开头、标题、结构和发布关键词。
- 改写草稿、拆解对标内容、做发布前方法检查。
- 决策分析、行动卡点诊断、目标澄清、概念拆解。
- 把散乱的内容和选题整理成可复用的资产结构。
- 保存和恢复工作状态，生成复盘报告。
- 知识库建设方法论和目录结构设计。

## 什么时候需要 API Key

当 Agent 需要让 san 后端服务实际查询数据、生成内容或调用外部工具时，需要配置 san API Key，包括：

- 搜索得到大脑知识库中的笔记和资料。
- 搜索小红书、抖音等公开内容和创作者数据。
- 生成内容配图、封面图等视觉素材。
- 调用其他需要后端计算的能力。

用户已给出明确任务且属于小范围时，直接执行；首轮最多做 5 次外部查询。
如果需要扩大范围、增加查询量或调用更高成本能力，说明新增的业务范围并请用户确认。

## 路由工作方式

你收到用户问题后，按以下流程工作：

### 第一步：读取路由索引

定位本 SKILL.md 所在目录，读取 `playbooks/router-index.json`。
这个文件定义了所有可用的 playbook、它们的分类、触发信号和输出物。

### 第二步：判断当前任务

从用户的问题中提取：
- 当前唯一任务是什么
- 属于哪个分类
- 用户期望的输出物是什么
- 已经提供了哪些材料

信息足以判断时直接选 playbook。只有一个缺口会实质改变方向时，才问 1 个问题。

### 第三步：选择 playbook

- 选 1 个主 playbook（role = primary）
- 最多选 2 个辅助 playbook（role = supporting）
- 不确定时选最接近的，不要纠结

### 第四步：读取并执行

读取选中的 playbook 文件（playbooks/xxx.md），按里面的方法论执行任务。

### 第五步：整合输出

把结果整理成人话，不要直接甩 playbook 的原始内容。

## 设计原则

1. **单任务原则**：每次只处理一件事，不贪多
2. **1+2 组合**：一个主 playbook + 最多两个辅助 playbook
3. **先诊断后开方**：先搞清楚问题，再给方案
4. **行动导向**：每个输出都要有下一步可以做什么
5. **总控路由**：用户不用记命令，说人话就行，你自己判断走哪个 playbook

## 用户偏好（强制执行）

1. 喜欢大白话，不要专业术语和官方话术
2. 喜欢简洁直接，不要啰嗦和废话
3. 喜欢直接干，不要给一堆选项
4. 讨厌敷衍，讨厌"已经列在上面了"
5. 说过一次的事情就要记住，不要重复问
