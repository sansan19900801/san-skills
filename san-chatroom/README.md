# san-chatroom · 多专家研讨室

> 按话题**先选理论、再选代表人物**，动态组建 3-5 位专家，支持**并行会诊、串行接龙、红蓝对抗、投票择优**四种讨论；主持人负责开场校准、逼出真交锋、扫盲区、点破核心矛盾并在限轮内收敛。不是拉一群名人念名言，而是让多个**可检验的理论框架**处理同一个问题。

## 它解决什么

一个问题同时被多种理论、立场影响，单一视角容易有盲区、容易自我确认时，让代表不同框架的专家发言、互相校正，由主持人收口，帮你做出更稳的判断；也能对一个方案做对抗式压力测试，或产出多套独立方案再选优。

适合：策略抉择、商业判断、方案权衡、给想法做压力测试、想听真正不同的声音。

不适合：查一个事实、让 AI 直接替你写稿、或只想按固定模板单人把问题挖透（那是 deconstruct / standard-answer 的活）。

## 四种讨论模式（默认并行会诊，其余按需切换）

| 模式 | 适用 | 专家能否互相看见 | 怎么进行 |
|---|---|---|---|
| **并行会诊**（默认） | 开放问题、广覆盖多视角 | 首轮隔离，第二轮起带上一轮观点 | 各自独立发言→主持人收口 |
| **串行接龙** | 要观点当场碰撞、层层推进 | 后一位看到本轮前面所有人 | 先回应最强对手论点再讲自己，末轮交叉质询 |
| **红蓝对抗** | 已有方案/主张要压力测试 | 双方全程可见、即时对辩 | 正方立论→反方攻击→回应，最多 3 回合，裁判对比"原始 vs 加固后主张" |
| **投票择优** | 要多套独立方案选最优 | 全程严格隔离 | 各自独立交方案，主持人按标准打分选优 |

口诀：开放理解→会诊；当场碰撞→接龙；测一个方案→红蓝；出多套选优→投票。说"让他们辩一辩 / 换成红蓝 / 各自独立给方案"即可切换。**四种模式是并列新增，不互相替换，不选就一直是默认会诊。**

## 主持人怎么工作

1. **开场校准**：摆明初始倾向与讨论目的，锁定"问题本质是什么、不是什么"，太大收窄、太小拔高。
2. **选模式**：按目标匹配四种模式之一，用户可否决切换。
3. **理论先行选人**：候选理论过 5 条筛选（命题清楚/经时间检验/可独立验证/能处理当前变量/材料足够），默认排除流量型 KOL；框架不重复，会诊/接龙/投票至少一位唱反调，红蓝双方对等。名单先给用户确认。
4. **按模式讨论**：该隔离的隔离（会诊首轮、投票全程），该交锋的交锋（接龙先回应、红蓝逐条对辩）；支持并行子 Agent 就用，不支持就主助手顺序扮演，跨平台都能跑。
5. **纵向追问**：观点发飘时向下问三层 Why、向上问三层 For What。
6. **主持人收口**：核心矛盾→共识分歧→远近里外四维盲区→费曼"讲人话"检查→结论建议（红蓝/投票替换为裁判结论/择优结论）。
7. **限轮收敛**：每轮标注共识/分歧变化，讨论最多 3 轮、红蓝最多 3 回合，僵持由主持人拍板并注明保留意见。
8. **可选纪要**：结束时问一句是否存档（含讨论模式、共识/分歧/攻防或方案对比、行动项）。

### 关键立场

- **模拟发言 = 基于公开理论框架的推演，不是本人原话**，不伪造引用、不编造观点。
- 全程不用表情符号，用清晰文字标签。

## 安装

把 `san-chatroom/` 整个目录放到 skills 目录（如 `~/.agents/skills/`），重启对应 Agent 即可。

## 与其他 skill 的分工

| skill | 分工 |
|---|---|
| **san-chatroom** | 多视角**碰撞、对抗、择优与判断**（本 skill） |
| san-chatroom-austrian | 固定奥派经济学框架的专题聊天室 |
| san-deconstruct / standard-answer | **单人**按固定结构把一个概念/问题挖透 |
| san-decision | 长期重大决策的知识建模 |
| san-knowledge | 把研讨纪要长期沉淀进知识库 |
