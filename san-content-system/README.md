# 内容结构化系统 Skill

> 把你散落在各处的旧内容，拆成可复用的积木。你只需要指定内容目录，AI 自动完成审计、建工程、拆内容单元、建主题地图和选题装配，让旧内容可以反复重组出新内容。

![内容结构化系统](https://img.shields.io/badge/version-1.0.0-blue) ![License](https://img.shields.io/badge/License-MIT-green)

一套面向自媒体人的内容资产工程化 Skill。它不是帮你整理文件夹，而是把大量文稿、推文、课程稿、案例素材拆解成 5 类可复用的内容单元（问题/概念/观点/案例/方案），建立主题地图和选题装配稿，让旧内容像积木一样重组为新文章、新脚本、新选题。

## 解决什么问题

- 写了几十上百篇旧稿、选题、案例却散在各处，想用的时候找不到、无法复用；
- 同一个观点或案例反复重写，旧内容一直沉淀不下来；
- 想让 AI 围绕已有素材持续装配新文章、新脚本，却缺一个结构化底座；
- 想在 Obsidian 里看清内容之间的主题关系。

它把存量文稿拆成问题 / 概念 / 观点 / 案例 / 方案 5 类可复用单元，建立主题地图和选题装配，让旧内容像积木一样重组出新内容。内容量一般要到 50 篇或 8 万字以上才适合建工程；单篇润色诊断请用 `san-content`。

## 核心理念

### 你只需要提供 1 类信息

| 你提供什么 | 怎么提供 |
|---|---|
| **内容目录** | 告诉 Skill 你的文稿放在哪个文件夹，哪些纳入、哪些排除 |

Skill 会先审计内容量够不够（50 篇或 8 万字以上），达标后才建工程。不达标会告诉你为什么、降级做什么。

### AI 自动完成其余工程

- 自动审计内容规模、来源类型和边界
- 自动建立完整工程骨架（8 个目录 + 4 个根级文件）
- 自动复制原始素材（不改原文件）
- 自动从样本中抽取首批内容单元
- 自动生成主题地图和选题装配稿
- 自动建立关系索引、去重索引和处理状态
- 自带 10 个 JS 脚本工具，索引和草稿生成可重复运行

## 五类内容单元

| 类型 | 缩写 | 是什么 | 举例 |
|---|---|---|---|
| **问题单元** | QST | 一篇内容回答的核心问题 | 「搞流量的内容为什么不赚钱？」 |
| **概念单元** | CON | 文中给出稳定定义的概念 | 「议程设置」「认知落差」「惰性知识」 |
| **观点单元** | OPI | 你对某个问题的判断和立场 | 「戒掉写干货，你才能赚到钱」 |
| **案例单元** | CAS | 支撑观点的具体事件、数据、故事 | 「修改封面标题后播放量涨 3 倍」 |
| **方案单元** | SOL | 明确的行动路径或操作方法 | 「先有产品后有内容，付款链接先发我」 |

拆成单元后，同一个观点可以配不同案例重组，同一个概念可以被多篇文章引用。

## 四档递进模式

```text
审计模式 → 样本模式 → 批量模式 → 全量模式
```

| 模式 | 做什么 | 升档条件 |
|---|---|---|
| **审计模式** | 统计内容量、判断边界、决定能不能建工程 | 内容量达标、边界锁定、输出目录确定 |
| **样本模式** | 挑 3-5 篇代表性文稿，抽出第一批内容单元 | 单元口径稳定、关系口径稳定、主题地图跑通 |
| **批量模式** | 按批次推进，每批复盘字段和规则是否稳定 | 连续 2 批无返工、抽查误判率低于 10% |
| **全量模式** | 滚动处理剩余库存 | — |

每档有严格闸门，不过闸不升档，防止大规模返工。

## 快速开始

### 方式一：直接指定目录

```text
使用 $san-content-system 帮我建内容工程。

内容目录：~/Documents/我的文章（替换成你自己的文稿目录）
排除目录：草稿箱、临时文件
优先处理：已发布的公众号文章
```

Skill 会先审计内容量，达标后开始建工程。

### 方式二：先审计再决定

```text
使用 $san-content-system 审计一下 ~/Documents/我的文章 这个目录，
看看内容量够不够建工程。
```

Skill 会输出审计结论，告诉你达标没有、建议怎么做。

## 适用场景

- 本地积累了 50 篇以上文稿，想系统盘活旧内容
- 想让旧文章里的观点、案例、概念可以被反复调用
- 想在 Obsidian 里看到内容之间的节点关系
- 想让 AI 以后能围绕已有素材持续装配新内容
- 已经不缺灵感，缺的是旧内容调用效率

**不适用：**
- 单篇文案润色和诊断（请用 `san-content`）
- 少于 50 篇或 8 万字的零散素材
- 没有明确内容边界就想全量处理
- 从零开始写新内容

## 自带工具

| 脚本 | 作用 |
|---|---|
| `init-content-system.js` | 初始化工程骨架 |
| `generate-source-registry.js` | 批量生成来源注册表 |
| `rebuild-processing-ledger.js` | 重建素材索引与待处理清单 |
| `generate-unit-draft.js` | 生成内容单元草稿 |
| `extract-sample-units.js` | 从样本文稿抽取第一批单元 |
| `assemble-topic-from-units.js` | 从现有单元装配新选题稿 |
| `generate-link-map.js` | 生成关系索引与总览 |
| `generate-duplicate-candidates.js` | 生成去重候选与冲突总览 |
| `fill-obsidian-links.js` | 把结构化 ID 补成 Obsidian `[[链接]]` |
| `summarize-system.js` | 输出当前系统总览 |

## 安装方法

### Codex

```bash
git clone https://github.com/sansan19900801/sansan-content-system.git
cp -R san-content-system ~/.codex/skills/
```

安装后可直接输入：

```text
使用 $san-content-system 审计我的内容目录。
```

### Claude Code

```bash
git clone https://github.com/sansan19900801/sansan-content-system.git
cp -R san-content-system ~/.claude/skills/
```

### 豆包 / WorkBuddy

```bash
git clone https://github.com/sansan19900801/sansan-content-system.git

```

把整个 `san-content-system` 文件夹放到对应工具的 Skills 目录即可。

## 与其他 Skill 的关系

| Skill | 关系 |
|---|---|
| **san-good-question** | 搭工程之前帮你把问题想清楚。问题说明书越清楚，内容单元抽取口径越稳定 |
| **san-content** | 处理增量：新内容发布前做诊断质检。content-system 处理存量：拆旧内容建积木库 |
