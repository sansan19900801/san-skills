# 好问题生成器 Skill

> 把模糊问题改写成 Agent 可推理、可批评、可验证的问题说明书。问题越清楚，AI 越能给你 hard to vary 的答案；问题越含混，AI 越依赖默认假设。

![好问题生成器](https://img.shields.io/badge/version-1.0.0-blue) ![License](https://img.shields.io/badge/License-MIT-green)

一套面向自媒体人、一人公司和 AI 实践者的问题澄清 Skill。它不直接回答你的问题，而是先帮你把问题问对——钉住现象、暴露冲突、补齐约束、找到反馈入口，然后判断这个问题能被 AI 自动化解决到什么程度。

## 解决什么问题

- 问 AI 的问题太笼统（「为什么我做不好」「这个能不能做」），得到的全是正确的废话；
- 说不清现象、冲突和约束，AI 只能靠默认假设瞎猜；
- 想判断一件事能不能交给 Agent / AI 自动完成，却不知道边界在哪。

它不直接给答案，而是把模糊问题改写成对象、目标、冲突、约束、反馈齐全、AI 可推理可验证的问题说明书，并评估这件事的自动化可解程度（A–D 档）。

## 核心理念

### 好问题先钉现象

不要直接问「为什么我做不好」「为什么没人买」「这个能不能做」。先把它钉成一个可以观察的现象：

- 坏问题：为什么我的内容没人买？
- 好问题：最近 10 篇小红书笔记收藏率高，但私信咨询少。

### 好问题要暴露冲突

问题的力量来自冲突。没有冲突，AI 只能泛泛分析：

- 数据冲突：打开率正常，但转化低
- 行为冲突：用户说感兴趣，但不付款
- 预期冲突：我以为这个动作有效，但结果没有变化
- 资源冲突：我想自动化，但关键判断只在我脑子里

### AI 需要约束场

AI 擅长在明确约束下搜索、组合、推理。问题说明书要给它 5 类约束：对象、目标、变量、约束、反馈。

## 五项检查

每个问题按 5 个维度评分（0-2 分，满分 10 分）：

| 检查项 | 问题 | 通过标准 |
|---|---|---|
| 对象 | 到底分析谁或哪件事？ | 有具体对象、场景或任务 |
| 目标 | 想解释、预测、改进，还是决策？ | 目标类型明确 |
| 冲突 | 哪里和预期不一致？ | 能说出异常、矛盾或断点 |
| 约束 | 什么不能改变？ | 至少 1 个真实约束 |
| 反馈 | 什么结果能验证解释？ | 有数据、行为、实验入口 |

- 0-4 分：松问题，不适合直接交给 AI
- 5-7 分：中等问题，可以先给低置信候选解释
- 8-10 分：好问题，可以进入候选解释和验证

## Agent 可解性判断

判断一个问题能被 AI 自动化解决到什么程度，按 6 个维度评估后输出 4 档：

| 档位 | 含义 |
|---|---|
| **A 档** | 可高度自动化，AI 可以直接执行大部分流程 |
| **B 档** | 可半自动化，AI 生成解释/方案，人类提供关键判断 |
| **C 档** | 可辅助推理，AI 负责澄清问题、整理材料 |
| **D 档** | 暂不适合自动化，先补边界、变量或反馈入口 |

## 4 种工作模式

| 模式 | 输入 | 任务 |
|---|---|---|
| A | 模糊问题 | 指出断点，改写成好问题草案 |
| B | 现象和背景 | 提炼冲突，生成问题说明书 |
| C | 自动化请求 | 判断可解性，拆出 AI 可做/人要判断的部分 |
| D | 清楚现象 | 生成 2-3 个候选解释并批评 |

## 5 种输出格式

- **格式 A**：默认输出（断点 + 清晰度 + 低置信解释 + 半成品说明书）
- **格式 B**：严格问题质量审计（评分表）
- **格式 C**：Agent 可解性判断
- **格式 D**：完整问题说明书
- **格式 E**：候选解释与批评（hard to vary 对比表）

## 典型场景

- 内容转化：为什么有人收藏但没人咨询？
- 主页承接：为什么目标用户点进主页后不留下来？
- 商业问题：我的课/虚拟产品为什么卖不动？
- Agent 自动化：这个流程能不能交给 AI？
- AI 变现：闲鱼提示词商品为什么有人看没人买？

## 与 san-content-system 的关系

本 skill 是内容结构化系统的前置工具。在内容工程中，QST（问题单元）的 `question_text` 如果质量不高，可以先用本 skill 把模糊选题改写成好问题，再落入内容单元。
